## Layout, persistence and closure

- Repeat decisive Azure and RunPod consent inspections in both supported themes,
  preserving the user's configuration by changing only the isolated fixture.
  Existing proportional type and theme tokens remain; danger/warning text readable.
- Resize to 800×600 and back with a bounded exact-window position/size trace. Scroll
  the overview as necessary; long group IDs wrap, acknowledgement and both buttons
  remain reachable without overlap or horizontal clipping. Check/Retry stay distinct.
- Opening inventory is not a live observation. Error/pending language must never
  imply stopped billing, cancelled work, deleted HPS or durable saved filesystem.
- RunPod's lost-response/restart limitation stays visible: fresh bare absence is
  unverified; it does not justify repeated Retry or a claim credentials alone fix it.
- Explicitly Close the overview and inspect a truly blank board, then close the
  exact owned GUI through the normal window-manager protocol early enough to prove
  exit before the original deadline. No key/Stop/Delete operation on close.
- Verify normal GUI and task-owned WM/display exits, absent owned display socket,
  unchanged fixture bytes/modes and unchanged pre-existing process identities.
  Preserve any failed shutdown as failed; do not infer WM delivery from a screenshot.

## Deterministic coverage and final gates

- UI callback tests, not native requests, cover missing/insecure/legacy/current
  schema refusal with unchanged bytes/version/journal and the current-schema
  positive control reaching core admission. No new store or migration.
- Unit/action tests cover coarse pin-free eligibility, exact summary/home/config
  consent, fresh Retry acknowledgement, Check routing, single flight, competing
  dispatch gates, hidden receiver drain, stale/disconnected results and no replay.
- Result tests cover every operation's allowed revision delta, retained identity
  and metadata, ordered/original timestamps, overflow, present/pending, newly
  verified absence, historical tombstones and unverified failures.
- Native does not fabricate pending provider work: synthetic result/counter tests
  establish that protocol; live screenshots establish layout and input behavior.
- Run full eight local gates on the final exact head, using private tmpfs fixtures
  with that qualification recorded. Then hosted review and current-head CI must
  settle. Neither CI nor this smoke proves live cloud deletion, billing cessation,
  HPS durability, backups or lost-response recovery.
- Save the bounded receipt, decisive screenshots and exact hash list privately.
  Remove this temporary plan only after an accepted native pass; do not remove any
