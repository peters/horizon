# Fresh remote workspace setup — temporary Linux validation plan

Validate the final UI candidate after the configured setup prerequisite, saved
Shell Start and repository Prepare changes have actually merged. Record exact
commit, binary and installed worker-image provenance. This plan is not a cloud
allocation or credential-transfer approval. Delete it after the native pass;
retain the completed private evidence outside the repository.

## Isolated baseline

- Use a task-owned persistent Horizon home, exact debug binary/PID, separate
  virtual display/window manager and synthetic repository/commands only. Inherit
  umask 077, unset HORIZON and use a sanitized child environment. Never
  reuse or signal an existing Horizon/Pi process or the user's display.
- Snapshot existing Docker resources. Use a previously reviewed local image by
  exact digest with its real installed tools, explicit local socket profile and
  empty disposable registry configuration. No image pull, ambient Docker context,
  real GitHub PAT or live cloud account is needed for this native lane.
- Unlike earlier seeded-inventory fixtures, the target workspace must not exist
  in the store before using New remote workspace. No private fixture API may
  create its record/allocation/key/worker. A separate synthetic Git fixture may
  serve repository data for the later Prepare action; record that distinction.
- Capture launch, idle and pointer-only behavior. Opening the overview and blank
  form must not access provider credentials, create resources or poll providers.

## Native primary flow

1. Open New remote workspace. With no selection or incomplete fields, Review
   must fail locally without creating store records, keys or containers.
2. Fill one explicit Local Docker profile, exact reviewed image digest, disk,
   synthetic owner/repository/commit/work branch, nested directory and literal
   Shell argv including spaces, quotes and empty arguments. Review and inspect
   every displayed field, generated owner/workspace identity, persistent billing
   statement and task-free boundary. No provider action has happened yet.
3. Cancel. Assert no new worker/record/key. Prepare again; Confirm remains
   unavailable until explicit consent. Changing session/config/selection or
   closing the overview invalidates the preview without starting anything.
4. Consent and confirm once. Record the displayed locator before completion.
   Repeated clicks must not create more records/generations/workers. Observe
   pending elapsed time and the detach-not-cancel explanation.
5. Verify exactly one fresh saved workspace and one worker, retained public/key
   identity and no saved command execution. Check saved setup manually; do not
   equate an observed allocation with Git/task readiness. Refresh the inventory
   explicitly and find the original workspace.
6. Through the actual merged Prepare UI, prepare the anonymous synthetic Git
   repository. Through the separate Start UI, explicitly start the saved task.
   Confirm exact commit/branch/cwd/argv, single task identity and a progress tail
   marker. No local PC-file relay or private seeding shortcut is permitted.
7. Create dirty tracked/untracked synthetic data remotely. Close the candidate
   normally; independently verify the original task progresses with zero
   attached clients. Relaunch the same home and inspect/reconnect the original
   workspace without setup or task replay. Verify identities and dirty bytes.

## Edges, layout and honest limits

- Exercise manual Check for a saved dormant/pre-intent interruption with fake
  provider tests; never repair a real fixture by fabricating its runtime state.
- Inject a lost channel reply and context drift in UI tests. Preserve the
  original locator and uncertainty; explicit New means another workspace, never
  a silent retry. No destructive cleanup is triggered by UI timeout or closure.
- Render synthetic pending states immediately before and at 90/180 seconds.
  Assert the warning/decision text and unchanged dispatch count; no real-time
  waiting is needed to exercise these boundaries.
- Cover RunPod's exact HPS/image consent and configured GPU/count/rate summary
  with deterministic rendering/core tests, without env keys or cloud allocation.
  The HPS ID is not ownership/exclusivity/content/durability attestation; the
  hourly compute ceiling is not an all-in or provider-enforced total budget.
- Capture baseline, resized/narrow form, long digest/argv, confirmation, disabled
  consent, result and reopened inventory in dark and isolated light themes.
  Scroll, keyboard focus, cancel and Fit must remain usable without overlap or
  accidental confirmation. Qualify exactly what Fit actually demonstrates.
- After all pending operations settle, compare idle with scripted pointer moves
  over the dialog and empty canvas. No repeated credential/provider/store work,
  continuous repaint or new allocations should appear.
