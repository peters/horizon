# Workspace request preview — temporary Linux smoke plan

Validate the exact final UI commit after the repository-preparation dependency
merges and the preview is integrated onto current main. This slice only reviews
local values: it does not create, save, authorize billing or recover a worker.
Keep provider creation, consent and Check absent. Remove this temporary plan only
after the completed native pass; retain private evidence outside the repository.

## Isolated baseline and invariants

- Use the exact debug binary with source/tree/Cargo.lock/binary hashes, an
  isolated persistent client home, synthetic Local Docker/RunPod profiles and
  unused task-owned Xvfb/display/window-manager coordinates. Unset HORIZON for
  the child, use umask 077 and a disposable noninteractive terminal command.
- Only bootstrap the owning client session/profile. Do not seed a remote
  workspace/allocation/key/worker or launch a Docker/Git fixture. Configure a
  deliberately nonexistent Docker socket; do not supply RunPod or GitHub keys.
- Inventory may report an absent control store. The New action must still work.
  Before and after each settled case prove no cloud workflow DB, remote identity
  directory, provider call, container or task was created by request preview.
- Bind native input/screenshots to the exact candidate PID/start identity and
  display. Preserve every pre-existing application, process and resource.

## Pure and integrated checks

- Keep parsing tests for no default profile/image/program, literal JSON argv
  (spaces, quotes, newline and empty arguments), exact commit, positive disk,
  optional panel directory and checked integer RunPod cents-to-micros conversion.
- Test missing/zero/fractional/overflow rate, missing HPS selection, malformed
  JSON and invalid core request without echoing the malformed payload.
- Exercise actual asynchronous core preview for Local Docker and RunPod with
  no home creation. Duplicate Review/New while pending must keep one request.
- Cancel, close or change owner/home/config while a deterministic result is
  pending: drop the late result, retain no review, never replay or restart.
- A disconnected preview thread reports definite noncreation, not provider
  failure or unknown cloud state. Cancel clears all transient form/review state.
- Gate New to an actual persistent Linux client and no conflicting pending
  remote action. Non-Linux and ephemeral sessions must not dispatch preview.
- Render both form and exact review, asserting the absence of creation, consent,
  credential, Check, connection or task-execution controls.

## Actual UI walkthrough

1. Launch and open Remote Environments with zero saved records. Capture baseline
   and confirm New remote workspace is visible with the preview-only boundary.
2. Open the blank form: no profile is selected. Review empty/invalid input and
   inspect fixed corrective messages, keyboard focus and unchanged resources.
3. Fill explicit Local Docker profile, digest-pinned synthetic image, disk,
   GitHub slug/exact commit/dedicated branch, nested cwd and literal Shell argv.
   Review; verify all exact values and the owner, proposed unsaved workspace ID,
   Docker endpoint, persistent-worker warning and "Nothing has been created".
4. Inspect that only Edit request and Cancel are offered. Edit retains entered
   values and removes the old review; changed values require another Review.
   Cancel closes the form without saving. Reopen and confirm it is fresh.
5. Repeat with RunPod profile, exact authorized HPS ID/DC/minimum size and an
   explicit whole-number compute ceiling. Check displayed GPU choices/count,
   pull-registration presence and warnings that HPS is not ownership/durability
   proof and the compute ceiling is not a total spending cap. No cloud call.
6. Change actual session/config while editing/reviewing; old data must disappear.
   Use deterministic channel tests for pending timing rather than artificial
   long UI waits. Repeated Review clicks must never lead to creation controls.
7. Capture dark and isolated light themes, normal and narrow viewport widths,
   long digest/argv wrapping, full form scrolling, keyboard Tab/Edit/Cancel and
   Escape dismissal. Resize/Fit should not overlap controls or lose access to
   the last field/buttons; identify the exact Fit interaction tested.
8. Compare settled idle and pointer-only movement across the modal and empty
   canvas. No continuous animation, repeated preview/store/provider access or
   all-environment per-frame work. Record a bounded trace and decisive images.
9. Close through the normal window-manager path, verify exit, relaunch the same
   home and prove the request was not persisted. Existing saved inventory and
   the separate Prepare/Start actions must retain their prior behavior.
