# Issue 1112 workspace toolbar validation (temporary)

Use a task-owned isolated desktop, private application state and exact frozen
candidate executable. Open the desktop in a native VNC Device panel in the current
workspace; establish actual presentation and advancing frames before interaction.
Save timestamped public health inspections, actual child PID/executable SHA256,
launch/resize screenshots and a scoped video; decode representative frames.
Never use the developer desktop or publish private application identifiers.

## Baseline and primary flows

1. Launch the repository default CPU cloud profile with disposable, owned resources.
   Record pre-provision, build/upload, provisioning, session setup and ready states.
   Determine separately whether deployment succeeds, worker runs and each requested
   session attaches. Do not infer attachment success from Ready or a live monitor.
2. Confirm the workspace shell and layout controls are visible throughout startup.
   Select each layout before readiness and verify it takes effect on arrival.
3. Read identity, worker status, attachment state, hourly rate, estimated current
   run and lifetime provider billing without scrolling. Verify unknown data never
   renders as a zero charge or a connected state.
4. Open configuration, activity/logs, companions and management independently.
   Preserve all existing information, resizing and confirmation behavior.
5. Observe a failed launch, reconnect and rebuild/restart; verify meaningful recovery
   and that changing progress never places another action under a stationary pointer.
6. Disconnect local attachment while the worker remains allocated. Verify the UI
   explains continuing charges and does not stop/delete resources implicitly.

## Edges, layout and persistence

- Exercise default and narrow windows, cloud resize, Fit, full screen and canvas zoom.
  Summary remains readable, long names/errors wrap or truncate intentionally, and
  there is no overlap with session panels, workspace drag/rename or close targets.
- Long logs: scroll away from the tail, hover controls and switch secondary views.
  Reserved scrollbar width and stable button positions must remain intact.
- Restore a previous session, manual layout, collapsed cloud and resized cloud.
  Existing terminal/browser/device panels retain geometry, membership and focus.
- Empty cloud, no worker, preparing, ready, stale/failed/missing billing, stopped,
  deletion pending and deleted: distinguish known state from estimates and unknowns.
- Cancel every resize/stop/rebuild/delete confirmation and verify no provider mutation.
  Perform authorized mutations only on disposable owned resources; inspect provider
  state and storage retention directly. Keep actual cloud proof separate from seeded
  presentation fixtures, which cannot prove provisioning or attachment.

## Current Linux result

The isolated native VNC pass verified default-closed disclosure, expansion and
collapse with both restored session panels still visible, manual-layout migration,
minimum-width rendering, native window resize, Fit, fullscreen and Activity scrolling.
The frozen candidate was verified against the actual child executable. Scoped video
was recorded and representative frames decoded. Fixtures and their viewers were closed.

The real default CPU launch validated source assets and built the image. Upload was
blocked by registry credentials: the existing publisher token was invalid and the
available replacement lacked package-write scope. The launch did not reach provider
provisioning; the saved operation remained prepared with no worker or worker spec.
Task credentials, private state and the unique local image tag were removed.
