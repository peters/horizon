# Resume and manage saved conversations

Right-click an agent panel's title and choose **Resume a session**. The menu shows how many conversations are available for that panel's provider and folder. Conversations already attached to Horizon panels are excluded. Browse older entries with Previous and Next; use Copy ID to copy an exact identity, or select a conversation to restart the panel with it.

The picker blocks underlying controls in its window. Click outside it or press Escape to dismiss it. While open, it refreshes the provider's saved conversations every two seconds, including when the panel is idle. Each provider refreshes independently, so an unrelated unreadable store does not block this list. Changes to a confirmed deletion's identities or folders cancel confirmation; Delete all also cancels when newly discovered conversations change its count.

For Codex and Claude, each entry has a Delete action. **Select sessions** supports selecting conversations across pages, then deleting the selection. **Delete all** removes all conversations currently listed for this provider and folder. The confirmation displays the count and scope before permanently deleting the saved conversations and their subagent history. Project files are retained. Cancel or dismiss the confirmation to keep the conversations.

Deletion runs in the background. Pending conversations cannot be resumed in Horizon. Successfully deleted entries leave the list; failures stay available and are reported under expandable details. The latest deletion result remains available when reopening the picker. Claude history is staged outside the discoverable store before removal; a staging failure restores the original transcript. If restoration itself fails, the conversation leaves the resume list and **Saved history needs recovery** identifies the intact recovery bundle and its original-path manifest. The retained manifest also prevents leftover artifact records from restoring the identity to the catalog after a refresh or relaunch. Restore the transcript before resuming; this outcome is reported separately from deletion and ordinary failure. A later cleanup error removes the conversation from the resume list but reports **Files awaiting cleanup** with the remaining bundle path; those files have not yet been permanently removed.

Codex deletion requires a local `codex` executable on PATH with `codex delete --force <UUID>` support (verified with Codex CLI 0.159.3). Horizon delegates removal to that command using the same HOME/CODEX_HOME as catalog discovery. Claude deletion scans the complete transcript and requires a consistent embedded session ID before removing it and its matching conversation artifact directory under `~/.claude/projects/`. Transcript records larger than 16 MiB (including the line terminator) stop deletion before any history is moved. Every present folder field must match the normalized selected folder throughout the complete transcript. Missing, conflicting, duplicate, empty or invalid IDs, conflicting or invalid folder fields, and malformed transcript records stop deletion without changing saved history; conversations in Claude's live-process registry are protected. Deletion stops if the registry cannot be read, exceeds 4,096 directory entries, or contains a non-regular, oversized (over 64 KiB), malformed or ambiguously keyed JSON entry, preserving saved history until liveness can be verified. Other providers retain resume/copy support and explicitly show deletion as unavailable.

“All” refers to the displayed catalog scope, not other folders, providers or undiscovered history. Provider catalog discovery limits still apply (Claude: 64 recent transcript files; Pi: 128; Grok: 1000). No saved-state format or migration changes are required.
